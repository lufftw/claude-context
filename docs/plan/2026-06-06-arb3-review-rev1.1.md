## Round 1 consolidated findings (deduped, severity-ranked, each with task/file:line + concrete fix)

### F1 — FATAL — `queryAll` consumes a non-existent `iterator.next()`; the real SDK iterator is async-iterable-only
**Where:** Hotfix Step 5 (plan lines 256-279), Step 1 probe (lines 188-191), Step 2 mock (lines 213-228).
**Ground truth:** `@zilliz/milvus2-sdk-node@2.5.10` `dist/milvus/grpc/Data.js:650-686` — `queryIterator` returns `{ currentTotal, [Symbol.asyncIterator]() { return { next() {…} } } }`. There is **no top-level `.next()`**. The plan's `await iterator.next()` (line 273) and the probe's `await it.next()` (line 190) both throw `iterator.next is not a function` against real Milvus. Reported independently by 4 of 5 reviewers.
**Fix:** drive the async-iterator protocol (see PATCH-SET-1 P3); rewrite the Step-2 mock to expose `[Symbol.asyncIterator]` (P2); make Step-1 probe use `for await` (P1).

### F2 — FATAL — drain loop double-appends the final batch (duplicate rows)
**Where:** Hotfix Step 5 drain loop (plan lines 272-277), Step 2 mock (line 210).
**Ground truth:** `Data.js:658-659` returns `{ done: true, value: lastBatchRes }` where `lastBatchRes` is the **previous non-empty batch** (line 676), not `[]`. The plan's loop does `if (batch.length>0) out.push(...batch); if (res?.done) break;` → final batch pushed twice. The mock at line 210 returns `{done, value: []}` (a fiction), so the unit test passes against code that double-counts on real Milvus — a capture/assertion-runtime-mismatch. Masked in `loadExistingFileHashes` by `relativePath` dedup (context.ts:847) but corrupts every other `queryAll` consumer (crash-recovery readback Task 2.4, raw-count gate Step 10). The `for await` fix (F1) resolves this because `for await` stops on `done:true` without yielding `value`. Reported by 3 of 5.
**Fix:** same `for await` rewrite as F1 (P3).

### F3 — FATAL — `queryAll` omits the primary key from `output_fields`, breaking keyset pagination (infinite re-seed)
**Where:** Hotfix Step 5 (plan 256-279), Step 8 (lines 320-327 passes only `['relativePath','metadata']`), Step 10 gate (line 337).
**Ground truth:** `Data.js:670-674` computes `lastPKId = lastItem[pkField.name]` from the query result rows; `getQueryIteratorExpr` (`utils/Function.js:147-168`) re-seeds from the min-PK (`''` for the VarChar `id` PK) whenever `lastPKId` is falsy. If `id` is not in `output_fields`, every page re-seeds from `''` → same first page repeatedly while `currentTotal` advances → readback is a duplicated subset, not a full scan. This is the exact resume-corruption the Hotfix exists to fix. Reported by report 1 (Finding 2).
**Fix:** always inject the PK into `output_fields` inside `queryAll` (P3 includes `[...outputFields, 'id']`); Step-10 gate must assert **distinct relativePath count**, not raw row count (P4).

### F5 — HIGH — `mergeAndWriteSnapshot` does NOT preserve `files` across sessions; the plan's premise is false → silent loss of completeness state

### F8 — HIGH — retry-via-republish lacks a settle-once latch + unconditional supersede-eviction → double-resolve / re-arm on non-timeout retries

## Residual risks accepted (with rationale)

- **Provisional timeout default is an owner/M1 decision** (spec §7, decision-log item 2). PATCH-SET-2's P43 surfaced a real arithmetic conflict (100-min default × 4 retries = 24M ms > the 2h broker ceiling). **Accepted** *only because* the patch-list converts the worst case into a **tested invariant** (`timeoutMs × (maxRetries+1) < 7_200_000`) with a concrete reconciled pair (`timeoutMs=1_800_000`, `maxRetries=3`); the numeric default remains the owner's measured choice. The invariant — not the number — is the binding gate. Residual: the shipped provisional could still amplify on a genuinely-slow-but-alive worker until M1; bounded by `maxRetries=3` and priority ≤ 7.
- **RESTful `queryAll` capped at one 16384 window (P24).** Accepted because the MCP uses the gRPC driver exclusively (per CLAUDE.md/Infrastructure Constants); the RESTful path is interface-completeness only. The plan must drop the "drains ALL rows" claim for it.
- **No DLX/DLQ, no producer/consumer split** (spec §13, decision-log items deliberately discarded). Accepted: the single-process stdio MCP's durable resume comes from Milvus + the lockfiled snapshot; importing event-crawler's async pattern re-introduces the gap-3 shared-reply-queue risk for zero benefit on this topology.
- **Cross-project shared-queue amplification under synchronized fleet retry** is mitigated, not eliminated, by jitter (P37) + `maxRetries=3` + priority ≤ 7 (P36) + default-on no-consumer fast-abort (P11). Accepted as residual; the `checkQueue` backpressure throttle is explicitly deferred (spec §13) until monitoring shows claude-context is a noisy neighbor.
- **The Round-4 trace is the one *unaccepted* residual.** The composition of P30+P31+P33 across the Task 1.4↔1.5↔1.6↔2.3 seam is the single item that keeps this NO-GO; it is not a risk to *accept* but a verification to *perform* before Phase-1/2 code.
